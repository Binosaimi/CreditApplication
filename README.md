## How to run the project

### Prerequisites
- Docker
- Docker Compose

Create a `.env` file in the project root:

```env
JWT_KEY=<your-jwt-signing-key>
```
Then run:
`docker compose up --build`

## Scope & Assumptions
- Requirements says "Block user from receiving a loan". It is assumed that a user is either a bank or a bureau user, based on the overall task. Therefore, I'm making the assumption that the block is on the customer, not the user.
- litigation table has "Load ID" as one of the data available. load ID has no meaning in this context. It is assumed that it's a typo, and it's referencing loan ID
- when a litigation starts, it is expected that a letter will arrive from the MOJ regarding the details. MOJ is not part of the system
- Next due payment: Loan repayments are assumed to be monthly and due on the same day of the month as loan_start_date. If that day does not exist in a given month, the final valid day of that month is used.
- Litigation state: Pending represents a loan currently in litigation. Innocent does not prevent the loan from being treated as legally clear.
- Credit score C: Guilty litigation that does not meet the time/amount conditions for an F grade is still treated as adverse credit history rather than equivalent to a clean A/B record.
- Authentication: Authentication is implemented using signed JWTs issued by credit.identity. The customer and loan services validate the token independently.
- Authorization: Roles are represented as Reader, Writer, and Admin. Role assignment is handled by the identity service.
- Development data: Seed data exists only to make the required functionality immediately testable after startup.

## Architecture Design
- Communication between services is synchronous HTTP.
- credit.identity does not need to be called for every request. It signs the JWT once during login, and the other services validate the signature, issuer, audience, expiration, and role claims locally.
- The solution is split by business capability.
### credit.identity Owns:
- Users
- Institutes
- Roles
- User-role assignments
- Password hashing
- JWT creation
### credit.customers Owns:
- Customer profile
- Loan eligibility / blocking
- Litigation
- Credit score calculation
- Next due payment aggregation
### credit.loans Owns:
- Loans
- Payment ledger
- Delinquencies
